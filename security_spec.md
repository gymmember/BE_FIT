# Security Specification & Threat Model for Brown Abs Gym Website

This specification outlines the data invariants, threat vulnerabilities, and adversarial payloads designed to verify the security of the Firestore database.

## 1. Core Data Invariants

1.  **Identity Lockdown**: A user profile document can only be owned, created, read, or modified by the authenticated user whose `request.auth.uid` matches the profile's `userId`.
2.  **No Identity Impersonation on Bookings**: A class reservation must belong to the logged-in user. The `userId` in the payload must strictly match the authenticated caller.
3.  **No Ghost Fields (Strict Keys)**: Updates or creations must not include unrequested, rogue fields like `isAdmin` or `isPremium` that bypass licensing.
4.  **Immutable Identity**: Once created, `userId` and `createdAt` are absolutely permanent and can never be mutated by a user update query.
5.  **Verified Email Mandate**: To execute writes (creations or changes), the user must have a verified email token (`request.auth.token.email_verified == true`), ensuring bot defense.

## 2. Threat Vector Checklist ("The Dirty Dozen" Payloads)

Here are the 12 adversarial payload designs that must be matched and strictly rejected by our `firestore.rules` engine:

1.  **Identity Spoofing - Profile Injection**:
    `{ "userId": "attacker_fake_123", "weight": 70, "height": 172, "bmi": 23.6, "category": "Normal", "goal": "Fat Loss" }` for user `authorized_user_789`.
    *Refusal Logic*: Must fail because the database matches the caller's ID against the path variable AND fields.

2.  **Ghost Field Privilege Escalation**:
    `{ "userId": "user_id_456", "weight": 70, "height": 172, "bmi": 23.6, "category": "Normal", "goal": "Fat Loss", "isAdmin": true, "super_access": true }`
    *Refusal Logic*: Strictly rejected via hasAll and size constraints during creation.

3.  **Denial-of-Wallet Path Poisoning**:
    Accessing `/user_profiles/REALLY_LONG_HACKY_ID_CONTAINING_MALICIOUS_STRINGS_BEYOND_128_CHARS`
    *Refusal Logic*: Blocked by `isValidId()` string length restriction on document IDs.

4.  **Negative Value Weight Exhaustion**:
    `{ "userId": "user_id_456", "weight": -500, "height": 175, "bmi": 19.5, "category": "Normal", "goal": "Fat Loss" }`
    *Refusal Logic*: Rejected by boundary value range validations in standard models.

5.  **Unbounded Spam Session Booking**:
    Booking a class using a guest profile without validating the owner's UID field.
    *Refusal Logic*: Enforced mandatory identity relationship checks.

6.  **Admin Impersonation Booking**:
    `{ "bookingId": "bk_999", "userId": "victim_uid", "userName": "Victim User", "userPhone": "9876543210", "classId": "hiit", "classTitle": "HIIT", "trainerName": "Sneha", "scheduleTime": "6:00 AM", "createdAt": "SERVER_TIMESTAMP" }` sent by `attacker_uid`.
    *Refusal Logic*: Rejects the message because `incoming().userId != request.auth.uid`.

7.  **Unverified Bot Reservation Spam**:
    An account with `email_verified == false` attempts to write bookings.
    *Refusal Logic*: Blocked by mandatory email-verified validator.

8.  **Voucher Cost Spoofing (Price Mutation)**:
    `{ "passId": "pass_101", "userId": "user_uid", "clientName": "Richie Rich", "planId": "champion-year", "planName": "1-Year Elite Champion", "payablePrice": "₹10", "sessionFrequency": 5 }`
    *Refusal Logic*: Price and tier attributes must be verified or restricted on modification. (Immutable once generated by voucher system).

9.  **Message Spammer Log Insertion**:
    Injecting someone else's chat message content into `/user_profiles/victim_uid/chats/attacker_msg_1`
    *Refusal Logic*: Path matches child keys where `/user_profiles/{userId}` requires `userId == request.auth.uid`.

10. **Immutability Breach on Member Passes**:
    Changing the `planId` or `payablePrice` of an existing membership pass via update.
    *Refusal Logic*: Denied. Only creations are allowed on passes; update operations are blocked.

11. **Client-Controlled Timestamp Spoofing**:
    Passing a future or historical client-side clock time as `createdAt` rather than `request.time`.
    *Refusal Logic*: Database strictly validates `incoming().createdAt == request.time`.

12. **Blanket Query Scraping Attack**:
    Issuing a blank `getDocs` or list request on `/bookings` without filtering by owner.
    *Refusal Logic*: Prevented by `allow list` checking that querying filters align with user authentication.
